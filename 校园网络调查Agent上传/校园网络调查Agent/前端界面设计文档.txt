# 校园网络调查 Agent：前端界面设计文档

## 1. 设计目标与用户

面向校园网络工程师，提供一个清晰的调查入口：输入网络现象，查看初步方向、调查线索和建议步骤。根据项目截图中“可解释调查”的目标，界面突出线索与结论之间的关系；本阶段只展示规则生成的初步建议，不声称已取得真实网络证据。

## 2. 视觉方向

采用选定的深色网络运维工作台风格：深青黑背景、低对比的面板边框和亮黄绿色重点色，辅以橙色提示，兼顾长时间阅读与关键操作识别。顶部的信号轨迹图采用同心圆、网格和节点，呼应网络调查主题；它是装饰示意，不代表实时拓扑或监测数据。中文正文使用微软雅黑等本机字体，英文编号使用等宽字体；无需联网下载字体。参考 `5-antho-front-design.md` 中明确审美方向、统一色彩和重视细节的原则，并结合示例包中前后端分离和同源接口的思路实现。

## 3. 信息架构与布局

- 左侧导航提供问题调查、示例场景和调查结果三个锚点，并显示本地服务状态；顶部标明演示环境。
- 首屏用标题和示意图介绍工作台目的；主要工作区以输入和结果两栏并置，便于对照。
- 输入区包含带标签的多行文本、字数提示、提交按钮和隐私提示；结果区展示初步方向、线索、建议步骤及结果局限，未提交时显示空状态。
- 下方示例卡片通过后端加载，覆盖拥塞、设备故障、Wi-Fi 干扰、路径变化四个演示场景。

## 4. 主要交互与状态

1. 用户输入现象，或选择示例自动填入后再修改；输入上限 2000 字，字数实时更新。
2. 点击“生成调查建议”后进入调查中状态，按钮暂时禁用，避免重复提交；空内容给出提示。
3. 成功时渲染类别、说明、线索列表和排查步骤，并提示结果尚待核验；失败时显示错误及未完成状态。
4. 初次加载时检查服务状态和获取案例；服务不可用时显示连接或加载失败提示。
5. 返回内容以文本节点呈现；结果区使用 `aria-live` 通知辅助技术，输入有明确标签，示例为可聚焦按钮。

## 5. 与后端的连接

页面使用同源 `fetch` 请求：`GET /api/health` 查询服务状态，`GET /api/cases` 获取案例，`POST /api/diagnose` 发送 `symptom` 并接收 `category`、`summary`、`evidence`、`steps` 和 `disclaimer`。后端同时托管页面，因此应通过本地服务地址打开，而不是直接双击 HTML 文件。

## 6. 响应式与可用性

宽屏采用侧边导航和双栏工作区；窗口宽度不超过 900px 时导航移至顶部、工作区变为单栏；不超过 600px 时示意图下移、案例单列排列，简化导航以节省空间。按钮、文本区域有悬停或焦点样式；适配仍需结合目标浏览器和设备继续测试。

## 7. 已实现与后续计划

当前已实现本地症状输入、示例填入、规则建议展示、服务状态和错误提示。系统不读取真实设备或网络指标，也没有实现大模型 Agent、真实工具调用、反证分析或交互式拓扑。后续可在后端支持真实结构化证据之后，增加可交互拓扑、工具调用时间线、支持和反对证据的关联展示及结果导出；具体行为以实际实现为准。
