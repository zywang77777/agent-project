# 校园网络故障调查 Agent：后端高层设计（HLD）

## 1. 目标与范围

系统面向校园网络工程师，围绕宿舍区高时延调查，组织现象、假设、工具、证据和结论，并以可解释的方式提供排查建议。本文以项目说明截图为依据；具体技术栈、接口及分期为设计选择。第一阶段聚焦本地可运行的前后端演示；完整 Agent 和评测属于后续目标，不应将演示规则判断描述为大模型推理或真实故障诊断。

## 2. 架构

```mermaid
flowchart LR
    U[工程师浏览器] -->|同源 HTTP| S[Python HTTP 服务]
    S --> F[静态前端文件]
    S --> A[API 与输入校验]
    A --> R[第一阶段：本地规则与演示案例]
    R --> O[类别、证据、步骤与局限]
    A -. 后续 .-> G[Agent 编排与调查 Skill]
    G -. 后续 .-> T[指标比较、路径检查与排队模型工具]
    T -. 后续 .-> D[模拟拓扑与指标 JSON / CSV]
    E[独立评测及标签] -. 仅评测 .-> G
```

第一阶段使用 Python 标准库 `ThreadingHTTPServer` 托管前端与 API，不需要第三方依赖。前后端同源，浏览器通过 JSON 交互。当前采用本地规则生成演示结果；无真实设备访问、持久化、用户鉴权或外部模型调用。仅面向本机课堂演示，不作为生产服务。

## 3. 主要模块

| 模块 | 第一阶段职责 | 后续扩展 |
| --- | --- | --- |
| HTTP 与静态资源 | 提供页面与健康检查，解析 JSON，返回错误 | 认证、权限与部署边界 |
| 案例目录 | 返回可供选择的模拟现象 | 加载版本化 JSON/CSV 案例 |
| 诊断服务 | 对用户文本进行本地规则匹配，返回解释和建议 | 引入模型驱动的假设与工具编排 |
| 工具与 Skill | 本阶段执行模拟指标差值与路径比较函数，尚无 Agent 自主工具调用 | 接入结构化数据与模型工具调用，按条件进行 M/M/1 估计；Skill 约束证据与不确定性 |
| 评测 | 本阶段不宣称完成 | 独立保存标签与预期判断；对三组方案做案例评测 |

## 4. 第一阶段 API 契约

| 方法与路径 | 请求 | 成功响应 | 错误 |
| --- | --- | --- | --- |
| `GET /api/health` | 无 | JSON：`status`、`mode` | 服务不可用时网络错误 |
| `GET /api/cases` | 无 | JSON：`cases` 数组，元素含 `id`、`title`、`symptom`、`description` | 服务不可用时网络错误 |
| `POST /api/diagnose` | JSON：`symptom` 字符串 | JSON：`category`、`summary`、`evidence` 数组、`steps` 数组、`disclaimer` | 空输入返回 HTTP 400，JSON `error` |

一次调查流程：用户输入或选择症状 → 前端发起诊断请求 → 服务校验输入并匹配本地规则 → 返回类别、演示性依据和建议 → 页面展示结果及局限。原样示例还会执行指标差值和路径比较；演示数据为人工构造，不代表采集到的真实测量值。自定义文本不会附带示例数值。

## 5. 完整系统的数据设计（规划）

- 拓扑：节点、链路、端点及容量；指标：时间、设备或链路标识、RTT、流量、利用率、队列、丢包率；路径记录：时间及有序节点序列。
- 调查记录：输入现象、假设、工具名称与输入输出、支持及反对证据、结论、置信或不确定性、建议及时间。
- 评测记录：案例 ID、配置、预测、真实标签、任务成功及证据完整度。真实标签与预期结论保存在独立评测数据中，不提供给 Agent。
- 字段单位、时间格式和缺失值语义需在数据集建立时明确；第一阶段没有实现以上数据存储。

## 6. 可靠性和安全边界

空输入应获得明确错误提示；浏览器遇到服务错误或离线时提示重试。演示模式明确说明证据和建议的局限。未来接入数据时需校验输入、约束可调用工具、只读取授权数据，审计调用且避免将敏感信息送入模型；设备更改应经工程师确认。M/M/1 模型依赖到达与服务过程、稳定性等假设，不满足时不得以估计值冒充实测。

## 7. 验证与后续工作

第一阶段检查服务启动、静态页面、健康检查、案例加载、有效请求与空输入错误，以及浏览器中从输入到结果的完整流程。后续至少构建五类案例，独立评测直接 LLM、Agent + Tools、Agent + Tools + Skill，记录任务成功率和证据完整率，分析失败或不确定案例，保留配置、数据、运行日志与报告。真实评测结果应在实验完成后记录，不预填成功率。
