# 高时延调查工作方法 v1

## 适用场景与边界
用于有基线和异常时期指标的模拟校园网调查。只读数据、提出建议，不扫描或配置真实设备。
数据来自模拟案例，证据支持程度仅对该数据集成立，不能把观察相关性宣称为真实网络因果证明。

## 专业知识
- RTT 包含往返传播、传输、处理和排队等影响；RTT 升高不等于拥塞。
- 链路速率、利用率、队列与路径需联合检查。路径相同仅削弱已测方向路径变化假设。
- 利用率较高只是线索；要查看队列是否增加、观测时间是否一致。
- 端口错误明显增加时检查设备因素；无线异常需与同地点有线测量比较。
- M/M/1：ρ=λ/μ，Wq=λ/[μ(μ−λ)]，W=1/(μ−λ)，λ、μ 为包/秒，公式结果为秒。
- 只在案例明确满足泊松到达、指数服务、单服务器稳态假设且 λ<μ 时估计；不满足时拒绝套用。
- 单队列 Wq 不能直接等同于 RTT，无法解释的剩余时延应列为限制。

## 调查步骤与工具选择
1. 把用户描述当作待查现象，至少提出两个候选假设；用户说“肯定拥塞”不是测量证据。
2. 调用 get_link_metrics 查询相关链路基线、异常指标和容量，不能先猜参数。
3. 调用 compare_paths 核对路径是否变化；必要时查询新路径上的链路。
4. 调用 inspect_access 检查端口与无线/有线对照，避免遗漏接入设备或无线问题。
5. 有排队参数时调用 calculate_queue_delay 核验假设；无参数时说明缺失。
6. 分别记录支持、削弱和不足的证据，必须引用真实返回的 E 编号。
7. 证据矛盾或不足时降低结论强度、说明缺什么数据，不强制只选一个故障。

## 验证与常见错误
核对单位、时间窗口、数据来源、参数与工具返回值。不得把缺失值当作零，不得编造测量、证据编号、置信概率。
缺失反向路径时不能声称往返路径都没变；高负载但队列正常不能单凭负载确定排队拥塞。
最终输出至少两条候选假设的支持/反对情况、结论、限制和与证据相符的行动建议。
