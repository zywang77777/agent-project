# 初版实现与验证记录

日期：2026年11月15日。

## 已完成

在原有深色前端基础上接入DeepSeek原生工具调用，实现一个轻量单Agent。提供四种工具、专业调查Skill、八组模拟案例、A/B/C配置、异步进度、原始工具记录下载及独立CSV存档。原有课堂规则代码已备份，不再作为新版调查逻辑。

## 核心检查

`tests/test_core.py`的5项检查通过：M/M/1公式与边界、禁止未查先猜参数、缺失值不当作零、路径与拓扑对应、Agent工具回传与伪造证据ID拒绝。最后一项使用模拟模型响应以避免API消耗，工具实际执行；这项单元检查不冒充在线模型验证。JavaScript语法检查通过。

浏览器验证了配置密钥、提交调查、进度更新、候选假设和证据显示、展开工具输入输出。宽屏双栏与窄屏单栏分别检查；截图保存在本目录。

## 两个有价值的问题

1. 首轮协议调试中，模型把证据引用写成不符合约定的格式，校验拒绝后反复提交。改为明确的单编号格式、返回无效引用和允许编号列表，A组原始数据单独分配R编号后，完整批次正常完成。旧失败批次和工具记录保留在results中，不能把它与修正后批次合并为同一协议。
2. C03的预设主类别是rate_drop，三组均给出congestion，所以自动指标均计为不匹配。检查C组解释可见，它实际上识别了8→4Mbps的容量下降及其引起的排队，问题涉及“主因标签”和“后果机制”之间的区别。正式评测要事先定义多因并存和根因优先的评分方式；本轮不追改答案提高数字。
